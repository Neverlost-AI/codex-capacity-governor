## Approved recording and comparison rules for a future implementation grant

### Link and authority

- A new governed-run record is logically distinct from T002's `UNGUIDED` run. Its immutable link points to one persisted `PreflightEvaluationAttempt.id`, that attempt's `ComposedPreflightRevision.id`, confirmation receipt ID and digest, project, preflight draft, scope, and exact provider/window/reset/bucket identities. The server reads and verifies those stored records; a client-supplied plan or result is never authoritative. The attempt must have `forecast.kind = FORECAST_EVALUATION` and `policy.kind = POLICY_EVALUATION`. Its original decision and `authorizesWork` value are copied/referenced for historical display, not recomputed at run creation.
- A unique attempt-to-run constraint enforces T6-3. **One run covers the bounded development attempt**, including ordinary coding, testing, validation, fixes, prompts and agent handoffs within that attempt. None of those activities alone starts a new run or requires a new evaluation. A distinct retry/new bounded execution after the run is concluded, or a materially changed scope/required bucket set, must use a newly reviewed revision and saved evaluation, consistent with T005's one-attempt-per-revision storage. Linking a historical attempt does not refresh its capacity observation or reauthorize work. A recorded run after `DEFER`, `NARROW`, or `STOP / PRESERVE` is visibly marked **work recorded despite a non-authorizing decision**; it is not upgraded to `PROCEED`. Saved input rejections, policy input rejections and `NOT_COMPOSABLE` results remain in attempt history. If work followed one, the existing T002 `UNGUIDED` path can record the facts without a fictional governed plan.
- Before run creation, the paired operator reviews the server-resolved exact attempt and explicitly confirms that it informed this particular run. A one-use, server-held challenge binds the admitted local session to attempt ID, revision ID/digest, receipt ID, result family, and sorted exact bucket identities. On submission the server re-reads the immutable attempt and consumes the matching challenge once; changed session, replay, stale challenge, missing attempt, project mismatch or bucket mismatch fails without creating a run. The server records actor reference, confirmation time and receipt/reference. A browser `trusted`, `guided`, `followed`, or normalized-actual flag cannot establish authority. F8's loopback/pairing/origin/CSRF limits still apply; neither actor string nor local session proves legal identity or real-world adherence.
- The operator separately chooses one adherence value. `UNKNOWN` is an explicit choice, not a silent default. `FOLLOWED` means the operator reports executing within an original `PROCEED` scope; the server rejects that label for a non-`PROCEED` decision. `PARTIALLY_FOLLOWED` requires a non-empty factual explanation of the deviation. `NOT_FOLLOWED` and `UNKNOWN` may carry factual notes. No value changes the original decision, Governor policy, run outcome, or comparison math. Display it as **operator-reported adherence**, never as independently authenticated compliance.

### Actual usage and evidence currency

- Each governed outcome version records Decision 0001's selected `COMPLETED`/`PARTIAL`/`FAILED`, independent validation result, failures, deferred work, notes and optional factual remaining snapshot. These are not derived from adherence or usage. T002 legacy `UNGUIDED` rows and their at-most-one-raw-entry-per-category contract are not changed or automatically imported into comparable actuals.
- A separate governed bucket-usage entry identifies the linked attempt's `bucketId`, `providerId`, `capacityWindowId`, `resetCycleId` and forecast bucket-profile version; usage category; nonnegative decimal input string; literal `PERCENT` or `BASIS_POINTS`; factual source reference; observed-at offset timestamp; and explicit operator review. At most one entry exists per exact bucket identity **and category** in one outcome version. `OTHER` remains available in legacy T002 raw records; a governed-run `OTHER` fact may be described in notes but is not a comparable T006 bucket-usage category. An omitted entry is unknown, never zero; zero requires an explicit entered `0` and review.
- Parse decimal strings exactly (no binary floating point, exponent, negative value, `NaN`, or `Infinity`). `PERCENT` converts by exact multiplication by 100; `BASIS_POINTS` is the same exact value. Retain raw input and exact normalized bp (including any fractional bp) without rounding or clamping; a value above 100% is not changed to 100%. Reject an observed time later than the server record time. The operator must explicitly answer whether the entry covers **only** the named capacity window/reset cycle, with no unexplained reset or unrelated activity. A confirmed answer is stored as a server-bound reviewed assertion; an unknown/negative answer preserves the raw fact but is `UNAVAILABLE` for comparison. The server records the local reviewer actor reference, review time, rule version and source; this is reviewed **manual** evidence, not authenticated provider telemetry.
- A bucket identity not in the linked attempt, a changed reset cycle, missing source, ambiguous cross-reset interval, absent implementation entry, unsupported unit, unreviewed or superseded evidence, or incompatible profile/version cannot be silently allocated or converted. Preserve the raw observation where valid, but return a typed comparison-unavailable reason. Never infer actual consumption from remaining capacity, share one entry across buckets, or infer `IMPLEMENTATION` from `CORRECTION`/`VALIDATION`/`OTHER`.
- An amendment references the immediately effective outcome version, includes a non-empty reason, and repeats the complete factual and per-bucket reviewed snapshot. The server rejects a stale predecessor and appends atomically; original and intermediate versions remain readable. A copied usage value must be explicitly reviewed again for the new effective version. Historical comparisons retain their original evidence/version references; a new comparison is derived for the current version without rewriting the issued forecast, original outcome or earlier comparisons.

### Comparison and history

- For each required bucket independently, a current compatible `COMPLETED` outcome with reviewed `IMPLEMENTATION` usage and an original issued forecast range invokes the existing Decision 0003 comparison: signed and absolute error against issued EXPECTED, range hit, and `CalibrationRatio = Actual / issued Expected`. Correction and validation usage remain separate displayed facts; they are not added to implementation usage or borrowed across buckets. A zero issued EXPECTED or missing/incompatible actual returns `UNAVAILABLE`, not division by zero or a fabricated accuracy result.
- Compatible `PARTIAL`/`FAILED` implementation consumption is labeled `LOWER_BOUND_ONLY`; it never becomes a full-completion error or calibration candidate. For missing, stale/superseded or incompatible actuals, show the raw facts with a typed unavailable reason, not a lower-bound label. No aggregate accuracy percentage or cross-bucket total is produced.
- History lists saved attempts even without runs, both `UNGUIDED` and newly linked governed runs without relabeling either, all outcome versions and their reasons, and per-bucket current/historical comparisons. A reopened result is clearly a decision **at evaluation time**, not current authorization. No T006 repository-to-forecast history loader is created; every later T005 preflight still supplies an empty candidate set.

## User path and allowed architectural surfaces

1. A paired local operator selects an existing saved `POLICY_EVALUATION` attempt. The UI shows the exact revision, receipt, forecast, decision, configuration/method/profile versions and historical notice. Rejected and non-composable attempts stay visible in preflight history but are not eligible for a governed-run link under T6-2.
2. The operator explicitly confirms that this exact evaluation informed one run. The server verifies the local session, one-use binding, same project/draft/scope, immutable attempt/receipt, bucket identities and unique run link. Restrictive decisions remain non-authorizing even when a later run is recorded against them.
3. The operator explicitly selects run outcome, independent validation and self-reported adherence; enters optional per-bucket/category usage, remaining snapshot, failures, deferred work and notes. Omitted usage is unknown. The UI shows raw values, exact converted window percentages/bp and reasons when comparison cannot be made; it never treats a browser trust flag as reviewed evidence.
4. A correction appends a complete reasoned observation referencing the current predecessor. Original and intervening observations, original T005 attempt, review evidence and comparison provenance remain recoverable. A new current comparison is derived without rewriting the issued forecast or an earlier comparison. A stale concurrent amendment fails.
5. Project/run history shows `UNGUIDED` and governed records distinctly, including saved attempts without runs, non-authorizing decisions, negative/incomplete outcomes, amendments and explicit unavailable reasons. It shows bucket identities and source units, never aggregates independent bucket capacities or offers an overall accuracy percentage.

Allowed implementation surfaces **after a separate grant**: `packages/contracts` additive governed-run, linkage, reviewed-normalization, comparison/adherence transport schemas; `packages/application` run/outcome/normalization/compare/history use cases and repository ports; `apps/web/src/server/db` additive persistence adapter/migration; `apps/web` paired local UI and accessible history; focused tests and implementation notes. Use `packages/forecast-engine` existing pure comparison semantics without changing formulas for outcome-only T006. A later history loader/V2 requires a separate approved assignment and pure-engine, contract, application and persistence boundary. The policy engine is read-only to this tranche.

## Accepted evidence and compatibility boundaries

- **Immutable linkage:** T6-2/T6-3 require a distinct additive governed-run relationship, one saved evaluable attempt per run and one run per attempt—not one run per prompt or agent. T002's `guidanceKind` contract and `development_runs_unguided_only` DB check currently admit only `UNGUIDED`; no placeholder `GUIDED` value or backfill is valid. Preserve legacy rows and create a reviewed additive migration/compatibility reader. Do not relabel an old `UNGUIDED` run because a plan exists later.
- **Authority and provenance:** T6-3's server-generated link receipt identifies the admitted local session, actor reference, system record time, exact attempt/revision/receipt, result family, bucket set and explicit operator confirmation. This is accepted *recording* evidence for a governed-run link under local F8, not proof of real-world adherence or legal identity. Upstream authentication remains deferred.
- **Actual compatibility:** Decision 0001's existing raw `amount`/`unit`/`source=manual` and remaining snapshot have no bucket identity or approved conversion to forecast bp. T6-5 instead requires a new per-bucket governed usage entry with its own retained raw value/unit and separately reviewed exact bp value. Direct `PERCENT`/`BASIS_POINTS` conversion is not a provider-credit mapping or permission to reinterpret T002 records. Preserve profile/method/version and raw-source provenance; invalid or superseded review cannot become a comparison candidate.
- **Recording versus interpretation:** Keep Decision 0001's outcome, validation, failure and deferred-work meanings unchanged. T6-4's adherence field is distinct and operator-reported, not inferred from outcome, validation, consumption, or policy result. Do not claim a Governor decision caused an outcome. Remaining-capacity snapshots are factual, not a derived reconciliation; any reconciliation rule is separate founder policy.
- **Comparison:** For a compatible `COMPLETED` run and bucket, report Decision 0003's `SignedError = Actual - issued Expected`, absolute error, range hit and `CalibrationRatio = Actual / issued Expected` using the immutable original forecast. Preserve exact and displayed values and explicit denominator identity. `PARTIAL`/`FAILED` normalized consumption may be shown only as a lower bound, never full-completion forecast error or calibration input. Missing outcome, missing category, zero expected, incompatible unit/profile/bucket, superseded or invalid normalization, and non-evaluable forecast return typed unavailable/non-comparable states; no fabricated zero. No overall accuracy percentage.
- **History query versus calibration loader:** T006 exposes factual and comparison history to users. It does **not** pass database candidates to `evaluateForecastV1`; T005 currently supplies `calibrationCandidates: []`, and later preflights stay cold-start. A future separate loader assignment must resolve candidate identity, recency/cohort, method/config/profile compatibility, evidence currency, immutable replay and historical reset-cycle treatment. Historical reset-cycle comparability is still deferred, not solved by a guessed identity join.

## Migration, rollback, tests and acceptance

The implementation proposal must show a forward migration from populated T001/T002/T005 records: an immutable governed-run/attempt foreign key with a unique attempt constraint; append-only outcome versions with at most one successor per predecessor and one initial observation per run; and per-version, per-bucket/category usage uniqueness. Exact physical layout may combine validated snapshots and relational constraints, but must preserve those logical invariants. No destructive rewrite, legacy backfill, or relaxation of `development_runs_unguided_only` is implied. Existing `UNGUIDED` rows and saved attempts must read identically. Preserve source and amendment chains. App rollback should leave additive evidence tables intact; dropping them would destroy history and requires separate authority. Historical comparison must be reproducible from the issued attempt plus effective reviewed actual and versioned normalization; corrupt or unverifiable snapshots fail visibly, never repair themselves.

Required evidence before review:

- Contract tests: every T6-2 result family; exact identity/uniqueness; four adherence values and `FOLLOWED`/restrictive conflict; explicit zero versus omission; decimal percent/bp equality including `1% = 100 bp`, fractional bp and above-cycle input without clamping; invalid/future/unreviewed source and timestamp; incompatible bucket/reset/profile; duplicate category; no arbitrary-unit/credit conversion.
- Application tests: paired-session success, one-use exact challenge, wrong-session/replay/stale/mismatched bucket/digest/project rejection, one-run-per-attempt collision, dependency failure without partial writes, no browser-authored guidance/normalization authority, and non-`PROCEED` linkage with no authorization claim. Prove coding, testing, fixes, multiple prompts and agent handoffs within one bounded run do **not** create another run or demand a new evaluation; a genuinely separate retry or changed scope/bucket set does.
- Comparison tests: Decision 0003's exact completed-run signed/absolute error, range hit and issued-expected ratio; partial/failed compatible lower bounds; missing, zero-expected, stale/superseded, ambiguous-cross-reset and incompatible actuals typed `UNAVAILABLE`; no cross-bucket substitution, no sum of correction/validation into implementation, no historical policy recomputation.
- Repository/migration tests: populated T001/T002/T005 fixtures survive, old `UNGUIDED` rows remain unchanged, original/linear full-snapshot amendment chain survives concurrent stale writes, unique attempt link and usage constraints hold, original and current comparisons remain reproducible, and app rollback reads old records without a destructive down migration.
- UI/browser tests: accessible labels and errors for explicit link/adherence/usage review, zero versus unknown, restrictive-deviation warning, historical decision-at-evaluation-time notice, current and superseded comparison details, and unavailable reasons. At least one paired Playwright path covers saved T005 attempt → explicit link confirmation → completed outcome/usage → comparison → reasoned amendment → historical reopen; separate negative paths cover an ineligible attempt, restrictive result, replayed challenge, and partial/failed lower-bound or unavailable state.

Run the existing T001/T002/T005 regressions, format check (distinguishing checkout line endings from committed-file format), lint, typecheck, full test, coverage, build, E2E, migration generation/check and `git diff --check`. Record exact counts and any environment limitations; never silently weaken a failing check. A separately approved loader/V2 would additionally require sequential repeated-workload and mixed-cohort deterministic tests from concern 001; it is not hidden inside outcome tests.

**Acceptance criteria:** (1) one exact server-confirmed, eligible attempt links to at most one bounded run; ordinary prompts, handoffs, coding, testing and fixes do not split it, and no restrictive result is displayed as permission; (2) all factual outcomes, validation, failures, deferred work, raw usage, operator reports and reasons reopen unchanged; (3) exact per-bucket manual percentages/bp are reviewed with source and cycle identity, with missing distinct from zero; (4) completed compatible implementation actuals yield reproducible Decision 0003 comparison, while partial/failed or incompatible evidence is distinctly lower-bound/unavailable; (5) amendment history is append-only and original forecasts/decisions remain immutable; (6) legacy `UNGUIDED` paths still work; (7) later preflights remain cold-start; and (8) the required tests and migration/review evidence pass. T007 dogfooding and any release decision remain separate gates.

Do not weaken tests to satisfy a gate. The implementer must stop for any **new** evidence authority, normalization, run-linkage, method, budget or public-contract semantic choice not settled here.
