## Boundaries and configuration

- `CAPACITY_GOVERNOR_MODE=local` (default) retains the supported loopback launcher, ingress proof and pairing. Never proxy/tunnel local mode. `hosted` activates a **separate** Google OIDC and database-backed session boundary; an unknown mode fails closed.
- `CAPACITY_GOVERNOR_ORIGIN` is the exact public HTTPS origin. Hosted mutations require matching Host and Origin. Google OAuth redirect URI is `<origin>/access/google/callback`. Preview/alternate domains are not interchangeable; each would need separate explicit review/configuration.
- `CAPACITY_GOVERNOR_FOUNDER_ISSUER` and `CAPACITY_GOVERNOR_FOUNDER_SUBJECT` are the exact allowlisted claims from a verified Google ID token. The `sub` is not an email address. No self-registration or participant allowlist exists.
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` identify the reviewed Google OIDC client. ID tokens are accepted only after signature, issuer, audience, expiration, issued-at and nonce verification. The authorization-code flow uses state, a browser-bound state cookie and S256 PKCE. Neither browser-supplied flags nor Vercel sign-in establish app identity.
- `CAPACITY_GOVERNOR_SESSION_KEY` must be a securely generated, stable, at-least-32-character secret shared across all app instances. Rotating it invalidates outstanding cookies/challenges; plan that as a controlled session revocation. Never log or commit its value.
- `DATABASE_URL` is the Supabase **transaction pooler** PostgreSQL URL for web functions. The Node `pg` pool is module-scoped with `max: 1`, TLS certificate and hostname verification, no session-level SQL state or named prepared queries. Set `CAPACITY_GOVERNOR_POSTGRES_CA_BASE64` to the Base64 encoding of the project's official Supabase root CA PEM file, downloaded from the Supabase project connection settings. The app rejects a missing or malformed CA; it never disables verification or guesses trust from the platform runtime. A URL `sslmode=require` is accepted and removed before `pg` parsing so it cannot override explicit certificate verification; other URL SSL knobs fail closed. Hosted request handlers do **not** run migrations. Use a separate limited application credential; do not expose it to browsers.
- `MIGRATION_DATABASE_URL` is a privileged PostgreSQL connection for a separately authorized, controlled migration job; never set it in Vercel web functions. Prefer the Supabase **direct** endpoint when the operator workstation supports IPv6. On an IPv4-only workstation, test the Free-tier **shared session pooler** on port 5432 for the job; do not use the transaction pooler for migrations or purchase the IPv4 add-on. Copy the exact hostname and username from the project's Connect panel, not from a constructed pattern. The web-function `DATABASE_URL` still uses the shared transaction pooler on port 6543. [Supabase connection guidance](https://supabase.com/docs/guides/database/connecting-to-postgres).
- `CAPACITY_GOVERNOR_HOSTED_TEST_AUTH=1` exists solely for loopback development and browser tests. It requires the supported loopback launcher, signed per-request raw ingress, loopback socket peer and a separate random `CAPACITY_GOVERNOR_HOSTED_TEST_SECRET` that is never rendered or logged. The test-sign-in route requires that secret and returns 404 when test mode is disabled; production and Vercel fail closed. Never set either test variable for a deployment.

## Google sign-in and founder allowlist setup

Once the approved hostname is known, register exactly `https://<approved-hostname>/access/google/callback` as an authorized redirect URI for the Google Web application OAuth client; if Google asks for an authorized JavaScript origin, use exactly `https://<approved-hostname>`. The app requests `openid`, constructs this callback from `CAPACITY_GOVERNOR_ORIGIN`, and rejects a mismatched callback/state. The scheme, hostname, and trailing slash must match Google's registered value exactly. Do not add Vercel preview URLs by default. Set up the consent screen and founder test-user access as appropriate for the private client, without enabling general registration.

Establish the allowlist **out of band** with a trusted local verification of the founder's signed Google ID token: check signature against Google's keys, issuer, audience/client ID, expiry and nonce; record only the verified `iss` and `sub` in protected configuration. A decoded-but-unverified token, email address, dashboard username, `hd` hint, or browser-supplied flag is insufficient. Do not send the token or client secret in chat or put either in logs. Configure both allowlist values before the first live sign-in; an unrecognized Google identity must fail closed. [Google's OIDC claim guidance](https://developers.google.com/identity/openid-connect/reference) identifies `sub` as the stable account key, and [Google's web-server guide](https://developers.google.com/identity/protocols/oauth2/web-server) requires an exact redirect URI.

## Migration and no-cost manual recovery procedure

After separate resource/configuration authorization, create the dedicated empty Free project and collect its **direct** connection (or shared **session** pooler for IPv4) in a protected operator environment. Before using a nonempty database, take and verify a backup. From the repository root at the authorized immutable SHA, set `CAPACITY_GOVERNOR_MODE=hosted` and `MIGRATION_DATABASE_URL` only in that protected job, then run `pnpm db:migrate`. The job applies the committed additive Drizzle journal `0000` through `0004`; request handlers must not migrate. Verify the `drizzle.__drizzle_migrations` journal, expected application tables, `owner_key` behavior and empty hosted project list. Do not run a down migration or import local evidence. Create/grant the limited application role only for the Governor tables after migration; validate its required reads/writes while denying schema changes. The privileged migration credential must not be the Vercel `DATABASE_URL`.

Supabase Free [does not include managed automatic backups](https://supabase.com/docs/guides/platform/backups). Use installed PostgreSQL client tools at a compatible version for a manual logical backup. Supply libpq connection fields (`PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`) through protected, temporary operator configuration, not command arguments or shell history; verify the source project reference and database before the command. On an IPv4-only workstation, use the project's shared **session** pooler, not transaction mode. Write the custom-format dump to encrypted storage **outside the repository** and retain a separate secure offsite copy without new spending. Include both the `public` app schema and Drizzle's migration schema:

```text
pg_dump --format=custom --no-owner --no-privileges --schema=public --schema=drizzle --file=<secure-external-path>/governor-<timestamp>.dump
pg_restore --list <secure-external-path>/governor-<timestamp>.dump
```

Record a SHA-256 of the dump and check that the archive lists Governor tables plus `drizzle.__drizzle_migrations`. Take a new dump before each migration and after each new run/outcome/amendment until a separate retention schedule is approved; do not delete earlier evidence backups by default. Avoid any cost-bearing storage product. If secure offsite storage is unavailable at $0, stop before measured use.

For a restore rehearsal, create a **new disposable local PostgreSQL database**, disconnect and verify that the restore connection targets only that database (never the source Supabase project), then run the following with credentials pointing to the disposable target:

```text
pg_restore --no-owner --no-privileges --exit-on-error --single-transaction --dbname=<disposable-local-db> <secure-external-path>/governor-<timestamp>.dump
```

Compare migration-journal entries, counts and representative project, evaluation, run, outcome and amendment IDs/content against a pre-dump manifest; confirm a second test owner cannot read the restored founder records through the app boundary. The dump may contain session/login material: restrict access and **revoke/rotate sessions before any live recovery**. Delete only the *disposable* restore database under separately checked local scope; never restore over or clean an existing Supabase project without a new explicit recovery decision. Free-project inactivity pausing and manual resume are operational risks, not substitutes for backups. Record export frequency, storage location, retention and restore time in the deployment go/no-go.

**Verification limit:** The accepted implementation already has a disposable PGlite data-directory export/restore test, and this preparation reran it in the 13/13 focused hosted/database tests. A real `pg_dump`/`pg_restore` rehearsal has **not** run: this checkout has no PostgreSQL client tools or Docker, and no new Supabase project may be provisioned under this grant. The PostgreSQL procedure remains a required setup-time test, not a claimed pass.
