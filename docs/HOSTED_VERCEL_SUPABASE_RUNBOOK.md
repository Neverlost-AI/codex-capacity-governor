## Boundaries and configuration

- `CAPACITY_GOVERNOR_MODE=local` (default) retains the supported loopback launcher, ingress proof and pairing. Never proxy/tunnel local mode. `hosted` activates a **separate** Google OIDC and database-backed session boundary; an unknown mode fails closed.
- `CAPACITY_GOVERNOR_ORIGIN` is the exact public HTTPS origin. Hosted mutations require matching Host and Origin. Google OAuth redirect URI is `<origin>/access/google/callback`. Preview/alternate domains are not interchangeable; each would need separate explicit review/configuration.
- `CAPACITY_GOVERNOR_FOUNDER_ISSUER` and `CAPACITY_GOVERNOR_FOUNDER_SUBJECT` are the exact allowlisted claims from a verified Google ID token. The `sub` is not an email address. No self-registration or participant allowlist exists.
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` identify the reviewed Google OIDC client. ID tokens are accepted only after signature, issuer, audience, expiration, issued-at and nonce verification. The authorization-code flow uses state, a browser-bound state cookie and S256 PKCE. Neither browser-supplied flags nor Vercel sign-in establish app identity.
- `CAPACITY_GOVERNOR_SESSION_KEY` must be a securely generated, stable, at-least-32-character secret shared across all app instances. Rotating it invalidates outstanding cookies/challenges; plan that as a controlled session revocation. Never log or commit its value.
- `DATABASE_URL` is the Supabase **transaction pooler** PostgreSQL URL for web functions. The Node `pg` pool is module-scoped with `max: 1`, TLS certificate verification, no session-level SQL state or named prepared queries. A URL `sslmode=require` is accepted and removed before `pg` parsing so it cannot override explicit certificate verification; other URL SSL knobs fail closed. Hosted request handlers do **not** run migrations. Use a separate limited application credential; do not expose it to browsers.
- `MIGRATION_DATABASE_URL` is a **direct** PostgreSQL connection for a separately authorized, controlled migration/backup job. Do not set it in the Vercel web-function environment unless operationally required and reviewed. Supabase documents direct connections for migrations and transaction pooler connections for serverless workloads: [connection guidance](https://supabase.com/docs/guides/database/connecting-to-postgres).
- `CAPACITY_GOVERNOR_HOSTED_TEST_AUTH=1` exists solely for loopback development and browser tests. It requires the supported loopback launcher, signed per-request raw ingress, loopback socket peer and a separate random `CAPACITY_GOVERNOR_HOSTED_TEST_SECRET` that is never rendered or logged. The test-sign-in route requires that secret and returns 404 when test mode is disabled; production and Vercel fail closed. Never set either test variable for a deployment.

## Local checks before a deployment request

1. From the repository root, run `pnpm install --frozen-lockfile`, `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:coverage`, `pnpm build`, `pnpm test:e2e`, `pnpm db:generate`, and `git diff --check`. The E2E command includes the old local-pairing suite and a separate two-phase hosted-like browser suite with disposable local identities and PGlite. The hosted suite stops and restarts the Next process, then signs in anew and reopens the same database evidence.
2. Review the additive migration `apps/web/drizzle/0004_mute_black_bolt.sql`: existing projects receive only the `local:legacy` owner key; no historical project, preflight, evaluation, run, outcome or amendment evidence is rewritten. New hosted projects use the verified issuer/subject owner key. Do not import local history into a hosted database implicitly.
3. The disposable PGlite dump/restore integration test proves local export/restore of app rows and owner isolation. It is **not** proof of Supabase backup retention, `pg_dump` compatibility, point-in-time recovery or live restore. Verify those independently on a disposable Supabase project after provisioning authority.
4. Record exact code SHA, migration journal, method/policy configuration versions, local test results, reviewer verdict and limitations. No measured T007 attempt or forecast-accuracy claim follows automatically.

## Separately authorized real-service sequence

1. Confirm the existing Vercel/Supabase plans, whether a separate Governor database/project is available, incremental monthly charges, backup retention, domain and Google client/subject. Founder approves a monthly ceiling and alert plan **before** provisioning. No actual cost has been verified by this local implementation.
2. Provision a dedicated private Governor Supabase project/database and reviewed credentials. Keep future sanitized demo storage physically or credential-isolated. Configure a Vercel Node/Next.js project for `apps/web` in this pnpm workspace, pinned to a reviewed immutable SHA. Set secrets in the platform's protected environment, never Git or build logs. Disable automatic production promotions during a frozen measurement cohort.
3. On a disposable populated database, take a recoverable export, run `pnpm db:migrate` with `CAPACITY_GOVERNOR_MODE=hosted` and `MIGRATION_DATABASE_URL` set through the protected job environment, then verify all prior evidence and `local:legacy` ownership. Repeat the migration preflight on the intended hosted database only after approval and backup. Do not run a destructive down migration: the new tables may contain evidence.
4. Deploy the exact reviewed commit to the fixed HTTPS origin. Verify Google callback and exact `(issuer, sub)` allowlist with real credentials, Secure/HttpOnly/host-only cookies, CSRF and Host/Origin rejection, sign-out revocation, expired sessions, one-use confirmation replay denial and no unauthenticated data route. Verify any required platform-side login throttling before public network exposure.
5. Use two separately authenticated test principals in an isolated test environment to exercise foreign project, evaluation, run, outcome and history URLs and writes. The production founder allowlist remains one principal; test principals are not admitted to it. Run the full input → exact review/confirm → evaluation → governed run → outcome → amendment → reopen path, including restart and restrictive/negative states.
6. With a **disposable** restored database, test a real PostgreSQL backup/restore and compare representative immutable evidence and migration journal. Review logs for secret/PII leakage. Record operational monitoring, stop procedure and rollback plan. A code rollback must not run the old loopback-only app against hosted traffic; retain additive tables and roll forward or restore a compatible reviewed build.
7. Founder separately decides hosted go/no-go and freezes deployment SHA, migration journal, auth/storage settings, challenge starters, model/settings and capacity ceiling before any measured TodoMVC, URL Shortener or Exercise Tracker attempt. A security or evidence-integrity change creates a newly labeled cohort.

Google, Supabase and Vercel live behavior, service cost, and backup guarantees remain **unverified** until those separately authorized checks occur. The local test identity proves code-path behavior only; it does not prove the Google callback or hosted platform configuration.
