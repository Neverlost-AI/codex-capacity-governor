# T007 prerequisite: private-hosted Capacity Governor foundation — DRAFT

**FOUNDER REVIEW ONLY.** This is a bounded implementation **proposal**, not a build, vendor-account, paid-provisioning or deployment grant. It precedes the separately authorized three measured T007 attempts in the [protocol](TRANCHE_007_INTERNAL_TESTING_AND_LOCAL_RELEASE_DRAFT.md). The accepted T005 loopback/pairing boundary is **not** a hosted login system; never expose it through a proxy, tunnel or host change. Keep the same Capacity Governor interface and Neverlost branding intended for a later portfolio demo, but do not publish actual records or invite Neo/others under this assignment.

## Objective and user-visible completion

Prepare a founder-only private hosted Capacity Governor that preserves the accepted manual, cold-start preflight → reviewed exact-input confirmation → policy result → governed run → explicit outcome/amendment → comparison/history/reopen workflow across restarts. The operator signs in, sees only their authorized records, and can reopen original and amended evidence after a new browser session and application restart. A separately authenticated test principal cannot read, mutate or confirm the founder's records, including by changing URL IDs. No measured attempt begins until a founder reviews the hosted security and persistence evidence.

## Exact allowed architectural surfaces for a later approved build

- `apps/web` hosted launcher/config, request/session/CSRF/access boundary, and narrowly necessary login/logout UI. Preserve the local supported launcher and its guards as a separate tested mode; do not make a single permissive host/origin switch.
- Framework-independent application authorization context and repository ports only as needed to enforce owner scoping. Keep pure policy and forecast engines, accepted schemas and arithmetic unchanged.
- PostgreSQL/Drizzle repositories and **additive reviewed** migrations for owner identity, durable sessions/challenges and integrity indexes/constraints. No destructive update/delete of historical attempts, governed outcomes or amendments. Specify the local-record owner backfill and rollback behavior before writing migration code.
- Deployment configuration, secret handling, controlled migration job, health monitoring, backup/restore procedure and documented rollback. No secrets in Git, logs, diagnostics or screenshots.
- Focused UI copy explaining founder-only private access and manual/unadjusted forecasts; the product interface, branded review/result/history views and accepted evidence limitations remain recognizably the same.

## Required implementation behavior and boundaries

1. Fail closed on missing/invalid hosted auth for every private page, API and mutation; accept only the founder allowlisted principal for the actual private service. A second *test* principal in isolated tests proves owner isolation but is not admitted to the deployed founder service. All auth/owner decisions are server-side. Enforce HTTPS, origin and CSRF checks on mutations; no unauthenticated ID enumeration or public read route to records.
2. Scope project lists, detail reads, revisions, attempts, run links, outcome versions, amendments and comparison/history queries to the verified owner. Cross-owner object IDs and inconsistent parent/child links fail without revealing another owner's data. Race and transaction tests cover one-use confirmations and owner-bound writes.
3. Preserve exact snapshot digest, required-bucket provenance, explicit work-input and bucket confirmations, non-authorizing outcomes, append-only amendment chain, original forecasts and decision-at-evaluation-time behavior. Session restart may require a **new** review/confirmation; it must not replay or silently authorize an old one. Do not recalculate history or activate the loader.
4. Use the dedicated hosted Postgres with durable migrations and an isolated test database. Reopen records after app/container restart and database reconnect. Prove an export/restore into a **disposable** DB without damaging the primary. Freeze deployed SHA, migration journal, config versions and auth/storage settings before T007 attempts.
5. Provide a controlled deployment runbook: reviewed branch/PR and founder approval; explicit provisioning/billing grant; migration/backup preflight; deploy exact commit; smoke/auth/isolation tests; founder go/no-go. Disable automatic deploy while the measured cohort is active. A security or evidence-integrity fix creates a new labeled cohort and needs renewed review.

## Verification and acceptance criteria for the later build

- Unit/application tests: verified subject allowlist, expired/revoked session, missing CSRF, malformed origin, exact snapshot/bucket binding, replay/concurrent confirm, local-versus-hosted mode separation and fail-closed startup.
- Repository/integration tests: owner scoping on **every** project→preflight→attempt→run→outcome/history path; guessed foreign IDs; cross-owner links; migration/backfill/rollback compatibility; append-only originals/amendments; PostgreSQL restart and isolated restore.
- Browser tests in hosted-like HTTPS/auth context: login, input → review → two confirmations → result → governed run → explicit outcome → amendment → reopen after session and app restart; restrictive/non-composable/rejection and save-failure states; unauthenticated and second-principal denial; local mode still passes its current E2E tests.
- Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:coverage`, `pnpm build`, `pnpm test:e2e`, `pnpm db:generate`, and `git diff --check`; report actual results and any checkout-line-ending exception honestly. Conduct independent exact-commit review before a deployment request.
- Hosted go/no-go: HTTPS and principal allowlist verified on deployed SHA; no public data route; private and demo datastore credentials distinct; persistence/reopen after restart; negative isolation/replay tests; backup/restore demonstrated; logs redact secrets; billing cap/alerts and incident stop procedure documented. The founder must explicitly approve measured use **after** this gate.

## Explicit exclusions and stop conditions

No automatic Codex balance retrieval, provider SDK, AI analysis, forecast formula/confidence/policy/reserve change, history loader or Decision 0005 activation. No general registration, Neo or other participant accounts, billing features, production-scale tenancy, public demo, public export, deployment by this draft, or T008 operations. The later public demo should receive only independently reviewed sanitized copies and use a separate static/isolated simulation boundary; it is **not** this private implementation.

Stop and request founder decision before implementation if the identity provider/principal, owner/backfill model, private-host billing ceiling, data-retention/export requirement, or hosted-vs-local access behavior cannot be implemented without changing accepted evidence semantics. Stop deployment if a route bypasses authentication, records cross an owner boundary, one-use confirmation can replay, migration/restore loses evidence, or vendor costs/permissions exceed the approved grant.
